# `@fdraft/theme-renderer`

A host-agnostic, DOM-based React renderer for validated `@fdraft/theme-sdk` documents. Studio, FDraft, and this repo's own `apps/renderer-lab` all render through the exact same implementation, supplying only their own injected asset resolver, component-adapter registry, and host settings — see `docs/architecture/TWO_REPOSITORY_ARCHITECTURE.md`.

## What's here

- **`ThemeRenderer`** (`src/ThemeRenderer.tsx`) — the single entry point. Takes a `RenderableDocument` (a `RuntimeThemeDocument`, or any equivalent shape — see `types.ts`), an `AssetResolver`, a `ComponentAdapterRegistry`, and a `{kind: "page"|"popup", ...Id}` target; renders it inside a top-level error boundary with a safe, host-overridable fallback.
- **Master inheritance** (`src/inheritance.ts`) — resolves a page/popup's full layer stack root-master-first, detecting a missing or circular chain defensively (the SDK already rejects these at validation time; this is a second, renderer-side guard). `applyMasterLayerOverrides` applies a page/popup's narrow per-inherited-layer `transform`/`visible`/`opacity` overrides (recursively into nested groups too) before the container's own layers are concatenated on top — the single resolution path both real rendering and Studio's "detach from master" materialization reuse.
- **Layers** (`src/layers/`) — one view per SDK layer type (image, text, shape, group, slot, component, effect), each wrapped in its own error boundary so one bad layer can't blank a valid page. Every layer's positioned wrapper carries stable `data-fdraft-layer-id`/`data-fdraft-layer-type` markers Studio's Design Mode selection overlay reads directly — plain data attributes, no editor code in the render path. A group's own wrapper spans the whole stage but is `pointer-events: none` (it has no visual footprint of its own); every real layer type explicitly re-enables `pointer-events: auto` so it stays clickable regardless of which group(s) it's nested inside — without this, a group placed above other content in z-order would silently swallow clicks anywhere on the canvas. `ShapeLayerView` resolves `fillGradientTokenId`/`cornerRadiusTokenId`/`shadowTokenIds` to CSS via `src/tokenStyle.ts` (a gradient fill takes precedence over a solid one; multiple shadow tokens compose into one `box-shadow` list); `TextLayerView` applies `fontWeightOverride`/`lineHeightMultiplier`/`letterSpacingPx`/`wrap`.
- **Responsive layout** (`src/responsive.ts`, `src/transformStyle.ts`) — every layer is positioned as a percentage of the theme's design canvas inside a scaling stage (`aspect-ratio` + `container-type: inline-size`), so both geometry and text size (via `cqw` units) scale continuously; named breakpoints additionally override transform/visibility at specific widths. Only single-edge/center anchoring and one-active-breakpoint transform overrides exist — nine-point anchor *stretch*, fixed/fill/hug sizing, margins, min/max constraints, and proportional scaling across breakpoints are not implemented (see `docs/IMPLEMENTATION_STATUS.md`'s Phase 7 row).
- **Component adapters** (`src/componentAdapters/`) — themes reference opaque `componentKey` strings, never React imports. A host supplies a `Record<string, ComponentAdapter>`; an unresolvable or missing-adapter component key renders a visible compatibility fallback instead of blank space. `sampleAdapters.tsx` is a 16-component deterministic sample registry (page title, event information, event countdown, draft controls/progress, film grid/card, event progress, points counter, profile badge, generate-draft action, complete/watch action, challenge card, event navigation, results/completion content) proving the architecture — never a copy of real FDraft business logic. Every adapter reads its visible copy from `props.copy`, resolved per `ComponentCopyContractRegistry`/`ComponentCopySlotDeclaration` (`src/copyResolution.ts`'s `resolveComponentCopy`) — a slot declares default/fallback text, required/optional, allowed typed placeholders (substituted from `RenderState.placeholderValues`), and character guidance; a *required* slot can never resolve to an empty string. This registry is additive alongside `ComponentAdapterRegistry`, not a breaking change to it — `createSampleCopyContractRegistry()`/`SAMPLE_COPY_CONTRACTS` supply Studio's/renderer-lab's sample set. See `docs/architecture/RENDERER_HOST_NOTES.md` for read-only notes on what FDraft's *real* adapters will eventually need (Prompt 10).
- **Conditions/interaction states** (`src/conditions.ts`, `src/interactionState.ts`, `src/variables.ts`) — evaluates the SDK's closed, declarative `Condition` union against host-supplied `RenderState`: active image-state-group selections, event phase, and (new) the full `RuntimeVariable` set via `readRuntimeVariable`/`compare`/`inRange`/`boolean` nodes — event/profile context, current page/popup, performance tier/reduced motion (from `HostSettings`), and per-layer `interactionFlag` (hover/focus/pressed/selected). Never executes theme-supplied code; a missing/undisclosed variable value never throws, it simply makes every comparison false.
- **Behaviour rules** (`src/behaviourResolve.ts`) — the one shared, deterministic evaluator both Studio's preview and FDraft's real runtime call, never a host-specific interpretation. `resolveActiveBehaviourRules` resolves every `whileTrue` rule's effect on one `RenderState` snapshot at once: rules never see each other's resulting overrides within a pass, so it's a single non-recursive walk that cannot hang at runtime regardless of what a theme declares. Conflict resolution is deterministic — higher `priority` wins, equal priority breaks to the later-declared rule — and every call returns a full `BehaviourResolution.trace`: every candidate rule for every contested target, whether it won, lost, was disabled, or had a false condition (now including `animationActiveOverrides`, keyed by animation id — see Animations below). `resolveTriggeredRule` does the same for edge-triggered rules (`pageEnter`/`click`/`hoverStart`/… and `conditionBecomesTrue`) — the host decides *when* to call it (the actual click, the actual page transition, its own before/after diff for a `conditionBecomesTrue` edge) and is responsible for executing the winning rule's actions itself (navigation, popup open/close, `restartAnimation`); this function only ever returns data. Real hover/focus/pressed/selected support lives in `LayerFrame.tsx`: native pointer/focus/click events are wired to an optional `onInteractionFlagChange` host callback — never internal renderer state, keeping `ThemeRenderer` a pure function of its props — with `applyInteractionFlagChange` as the exported pure-update helper a host folds into the `RenderState` it re-supplies next render. `ComponentLayerView`/`ImageLayerView` resolve an active `setEnabled`/`applyStyleOverride`/`selectCopyVariant`/`setImageState` override ahead of the layer's own static configuration and the host-supplied active state, respectively. See `test/fixtures/candyBowl.test.ts` for a worked example (a three-state image-state group switching at configured, boundary-exact progress ranges) and `docs/IMPLEMENTATION_STATUS.md`'s Phase 8 row for the full registry and test evidence.
- **Animations** (`src/layers/useLayerAnimation.ts`, `src/animationPresets.ts`) — real CSS-keyframe playback for `AnimationDeclaration`, sharing one resolution path with Studio's preview and FDraft. `onEnter` plays automatically from mount (`repeat: infinite` is how a continuously-looping idle motion — float/wobble/pulse/sway — is built, no Behaviour rule needed); `onExit` keeps the layer mounted and playing for its full duration before the layer actually hides (previously impossible, since `visible: false` hid a layer instantly); `manual` never self-triggers — it plays only while `BehaviourResolution.animationActiveOverrides[animationId]` is true, which a `whileTrue` Behaviour rule with an `interactionFlag` condition sets, giving "on hover/focus/pressed" for free from the existing evaluator. 10 built-in presets (`fade`/`rise`/`fall`/`slideLeft`/`slideRight`/`scalePop`/`float`/`wobble`/`pulse`/`sway`) resolve to fixed keyframe shapes scaled by `intensity`; a hand-authored `keyframes` list (up to 12 steps) resolves through the same custom-CSS path. A deterministic, per-(animation, layer) seeded jitter (`randomOffsetMs`) staggers repeated copies of the same animated layer without ever being irreproducible. Both `reducedMotion` and a performance tier with `animationsEnabled: false` make animation resolution a complete no-op.
- **Effects** (`src/particleEngine.ts`, `src/layers/EffectCanvas.tsx`, `src/layers/FilmGrainEffect.tsx`, `src/performanceCaps.ts`, `src/usePlaybackGate.ts`, `src/seededRandom.ts`) — one shared canvas particle engine serves 10 particle-based `EffectKind`s (`rain`/`snow`/`fog`/`leaves`/`dust`/`stars`/`embers`/`confetti`/`fireflies`/`clouds`) through a single per-kind config table (motion pattern — fall/rise/drift/twinkle/wander — shape, colour, speed, sway, rotation, opacity-pulse); `filmGrain` renders through a separate, cheaper SVG `feTurbulence` path instead of being forced through the particle model. `PERFORMANCE_TIER_CAPS` is the real, structural protection against unbounded particles/effect storms: fixed, documented per-tier ceilings on particles-per-effect, simultaneous effect layers, and device-pixel-ratio — `EffectDeclaration.intensity` (0-1) only ever selects a point *within* the active tier's budget via `resolveParticleCount`, never a raw count. A seeded PRNG (`createSeededRandom`, mulberry32) makes every particle field's initial positions/sizes/phases exactly reproducible for a given seed. `usePlaybackGate` pauses the animation-frame loop when the document is hidden, the window loses focus, or the canvas scrolls offscreen (`IntersectionObserver`) — real pausing, tested with mocked browser APIs. Effect-layer-count capping is structural too: `ThemeRenderer` computes the allowed set (first `maxEffectLayers` in z-order) once per render before any effect mounts; anything beyond the cap renders nothing, not a degraded version. No blur/shadow filters are used anywhere in the particle engine — a deliberate cost-avoidance decision.

## What this phase does not implement (reserved gaps)

- Crop `width`/`height` (zooming into a sub-rectangle of a source image) — only crop position is applied today.
- True device-pixel-constant responsive anchors — anchor offsets scale with the canvas like everything else, since this phase's pure-CSS stage doesn't measure actual rendered size.
- Loading a text layer's bundled font asset via `@font-face` — only a font token's generic `fallbackFamily` is applied so far.
- Parent-relative nested layer coordinates — every layer's `transform` is canvas-absolute regardless of group nesting depth.
- Nine-point anchor *stretch*, fixed/fill/hug sizing modes, 4-sided margins, min/max width/height constraints, and proportional scaling across breakpoints (Prompt 7) — only single-edge/center anchoring and one-active-breakpoint transform overrides exist.
- `ZoneKind` (header/sidebar/main/overlay/footer, on `ComponentLayer`) is a logical classification tag only, checked by `@fdraft/theme-sdk`'s `checkDesignWarnings` — there is no resizable, visual zone-region layout system.
- `resolveTriggeredRule` correctly determines the winning rule for an edge event, but no host in this repo yet dispatches a *real* click/page-transition event into it and executes the resulting navigate/open-popup/close-popup/`restartAnimation` action — Studio only exercises the continuous (`whileTrue`) half of the evaluator live today, including real hover/focus/pressed/selected and (as of Prompt 9) animation start/stop.
- No custom-keyframe authoring UI exists in any host yet (Prompt 9) — the schema, this package's CSS generation, and its tests all fully support up to 12 hand-authored keyframes; only the UI to build one is missing.
- High-DPI canvas scaling (Prompt 9) reads and caps `devicePixelRatio` and is unit-tested, but has not been verified against a real physical high-DPI display.
- Audio is explicitly out of scope for this package (Prompt 9's own instruction) — no audio engine exists anywhere in this repo.

## Commands

```
pnpm --filter @fdraft/theme-renderer typecheck
pnpm --filter @fdraft/theme-renderer test
pnpm --filter @fdraft/theme-renderer build
pnpm --filter @fdraft/theme-renderer lint
```

## Versioning and distribution

Pre-1.0 (`0.1.0`), same experimental-contract status as `@fdraft/theme-sdk`. Released as an immutable, checksummed tarball attached to a `theme-renderer-v<version>` tagged GitHub Release — see `docs/architecture/COMPATIBILITY_AND_RELEASES.md` and `.github/workflows/release-theme-renderer.yml`.
